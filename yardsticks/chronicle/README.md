# dsh-chronicle 验证脚本 🔬

`dsh-chronicle`（会话实录投影）的两把尺子。原本丢在 `%TEMP%` 里，容易被清理掉，
2026-09-14 夜归档进来 —— **验器之器，也要当定制代码存**（戒慎第三条）。

> **为什么单列一处**：验证脚本不属于插件本体，混进 `06-插件补丁\dsh-chronicle\`
> 会被一并镜像进 profile 的 `node_modules`；故另立此目录存放。

---

## 一、目录

| 文件 | 管什么 | 尺子性质 |
|---|---|---|
| `test-v5.mjs` | 单元回归 **29 项**：路径形状（盘符 / 真 UNC / `\\?\` 设备与超长 / 正斜杠 UNC / 句末句号要剪掉）、**不该认的**（正则字面量、二次转写、单反斜杠碎片、四个反斜杠、网址不许切成半截路径、`file://` 不算路径、协议半截 `p://`、PowerShell 正则片段、路径拼接碎片）、归一（大小写 / 斜杠 / 尾斜杠 / UNC 不许与「从根」混）、分级（文件 / 目录 / 中文目录） | 验**形** |
| `agg-full-scan.mjs` | 全量独立复算：把 `~/.dsh/sessions/**` 全部会话日志**按会话分别**折叠一遍，出总账（会话 / 事件 / 实体分类 / 峰值 / `evicted` / `dropped` / 专题线 / 结局分布 / `stats` 累计），并拿原生 `turn/start` 数对账 | 验**账** |
| `rule-drift-check.mjs` | **口径对账**：把 `lib/projections.js` 的常量取出来，与 `README.md` 的「折叠规则」节、《DSH实录》里的表述逐条对读；不符则标 ❌ 并退出码 1 | 验**尺** |

两把尺子与 `lib/replay.mjs` **共用同一份折叠定义**，但**统计口径各自独立写** ——
这就是「不得与被测代码共用同一批对象」（戒慎第八条）的落法。

> `rule-drift-check.mjs` 起于 2026-09-14 夜《建言书》之争：**同一口径在三处有副本**
> （代码常量 / README / 实录），当下相符是**人勤**，不是**机制**。此尺即把那点人勤
> 换成一跑即知。**凡改口径（上限、条数、`stateVersion`），改完必跑此尺。**

## 二、怎么跑

⚠️ 两个脚本都要在**能解析 `zod` 的目录**下跑。最省事的办法：进 profile 里那份已部署的插件目录再调脚本。

```powershell
cd "$env:USERPROFILE\.dsh\profiles\web\node_modules\dsh-chronicle"

# 1) 单元回归（默认拿 profile 里部署的那份定义）
node "F:\AI\DSH\大肥鱼\06-插件补丁\dsh-chronicle-验证\test-v5.mjs"
#    → 通过 29 · 失败 0，退出码 0

# 2) 全量独立复算
node "F:\AI\DSH\大肥鱼\06-插件补丁\dsh-chronicle-验证\agg-full-scan.mjs"
#    → 打印总账 JSON + 末行「✅ 对账相符」；不符则退出码 1

# 3) 想拿工作区源码当被测对象（改码后、部署前先验）
node "...\agg-full-scan.mjs" "F:\AI\DSH\大肥鱼\06-插件补丁\dsh-chronicle\lib\projections.js"

# 4) 口径对账（不需要 zod，随便哪个目录都行）
node "F:\AI\DSH\大肥鱼\06-插件补丁\dsh-chronicle-验证\rule-drift-check.mjs"
#    → 末行「✅ 口径未漂移」；漂移则退出码 1
```

## 三、判定标准

| 项 | 合格线 |
|---|---|
| `applyErrors` / `schemaErrors` | **0 / 0** |
| `evicted` / `dropped` | **0 / 0**（LRU 生效则不该淘汰，更不该丢） |
| 单会话实体峰值 | 远低于 2000（若贴顶即该复查正则是否又放进了垃圾） |
| 对账 | `turn/start` = 已了结 + 进行中；`stats.turns` = 专题行合计（不含进行中） |
| 越界检查 | 带双反斜杠的实体应**逐条说得通**（`\\?\` 设备路径、文档引用、真路径本身）——详见报告第五节 |
